# Vector PDF Technical Drawing Parsing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a deterministic, resource-bounded vector PDF parser that maps
explicit title-block fields, drawing metadata, dimensions, and tolerances into
the existing Phase 1A canonical drawing contract with exact spatial provenance.

**Architecture:** Extend Phase 1A provenance with a typed PDF-point bounding
box, then implement `PdfDrawingParser` in an isolated module. pdfplumber runs in
a spawned worker process and returns a bounded immutable intermediate snapshot;
the parent performs deterministic recognition and canonical population. Every
unsupported or unsafe condition is fail-closed under the existing
`DrawingIngestionResult` status contract.

**Tech Stack:** Python 3.11+, frozen dataclasses, `Decimal`, pdfplumber 0.11.x,
stdlib `multiprocessing`, pytest, Ruff.

**Spec:** `docs/superpowers/specs/2026-09-22-vector-pdf-drawing-parse-design.md`

**Global constraints:** Do not modify frontend code, templates, routes,
database/schema files, CAD geometry/topology adapters, DXF code, OCR code, GD&T
recognition, or AI/VLM code. Preserve all pre-existing modified and untracked
files. Do not stage, commit, tag, or push unless separately authorized. Never
use broad cleanup or restore commands.

**Review focus:** fail-closed behavior, no content/exception leakage, exact
resource boundaries, deterministic ordering, conservative extraction, no
fabricated units or semantic entities, and backward compatibility with Phase
1A model construction.
